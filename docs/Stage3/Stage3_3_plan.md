# 第三階段－層級三：代理仲裁

## 實驗目的

層級三建立個案層級代理，整合單一專家模型、固定式融合與規則式融合的資訊，針對每個案例進行仲裁，選擇適合的候選結果並留下可追蹤的決策依據。

代理不直接修改模型參數，而是在既有候選分割中進行選擇或仲裁。

## 代理輸入

每個案例包含下列四類資訊：

1. **專家模型輸出**
   - 四個專家模型的機率圖與分割遮罩。
   - 各專家模型的信心分數、病灶體積、連通區塊與機率統計。
2. **層級一：固定式融合結果**
   - 硬投票、機率平均及加權機率平均的結果。
   - 層級一最佳固定融合候選及其摘要資訊。
3. **層級二：規則式融合結果**
   - 規則式系統的最終分割。
   - 被觸發的規則、調整後權重與不確定性標記。
4. **個案層級摘要**
   - 病灶大小、病灶候選數、預測一致性、模型信心及其他可解釋的個案統計。

## 代理任務

- 比較各候選分割的可信度與一致性。
- 根據個案層級摘要選擇單一專家模型、層級一或層級二的結果。
- 當所有候選結果分歧過大或信心不足時，將案例標記為不確定／需要複核。
- 輸出結構化的選擇結果與理由，確保決策可重現、可稽核。

## 建議輸出格式

```json
{
  "case_id": "case_xxx",
  "selected_source": "expert_0 | expert_1 | expert_2 | expert_3 | level_1 | level_2",
  "confidence": 0.0,
  "review_required": false,
  "reason_codes": [],
  "summary": ""
}
```

`confidence` 的定義與校正方式須在驗證集上固定；`reason_codes` 應使用預先定義的有限集合，避免只留下無法統計的自由文字。

## 實驗與限制

- 代理可使用的資訊必須在推論時實際取得，不可使用真實標註或由真實標註衍生的特徵。
- 提示、決策規則、候選結果與輸出結構在測試前固定。
- 若代理具有隨機性，需固定隨機種子／溫度，或進行多次執行並回報穩定性。
- 所有案例應保存輸入摘要、選擇結果、理由與執行版本，以便重現。
- 代理的選擇不應覆寫原始專家模型與融合輸出。

## 評估方式

### 分割效能

- Dice、Sensitivity、HD95、Precision、Specificity。
- 與最佳單一專家模型、層級一及層級二結果比較。

### 仲裁品質

- **理想選擇差距：** 代理結果與「每個案例事後最佳候選」之間的差距。
- **選擇準確率：** 代理是否選到該案例表現最佳的候選結果。
- **複核率：** 被標記為需人工複核的案例比例。
- **失敗捕捉率：** 低品質案例中被成功標記為需複核的比例。
- **決策穩定性：** 相同輸入重複執行時，選擇結果的一致程度。

## 消融實驗

依序移除不同資訊來源，以分析各類輸入的貢獻：

- 不提供單一專家模型統計資訊。
- 不提供層級一結果。
- 不提供層級二規則與觸發紀錄。
- 不提供個案層級摘要。
